# 2026-10-01

## 思维流体反应：四种结晶方块 + 两种碎片

### 新增内容

- **物品**：`inspiration_shard`（灵感碎片，匠魂碎片风贴图，投入机器充能槽折算 100 mB）、
  `mind_crystal`（思维晶体，紫水晶风贴图，暂无用途）。
- **方块**（`block/custom/`，一类一个文件）：
  - `DilutedInspirationCrystalBlock`：稀释灵感结晶，`HalfTransparentBlock`，半透明。
  - `ConcentratedInspirationCrystalBlock`：浓缩灵感结晶，同上但贴图几乎不透明。
  - `InspirationGelBlock`：灵感凝胶，继承原版 `SlimeBlock`（弹跳 / 免摔落 / 减速全来自父类）。
  - `MindCrystalRockBlock`：思维水晶岩，普通 `Block`。
  - `MindFluidBlock`：思维流体方块，接管放置与邻居更新两个时机做反应判定。
- **配方**：思维流体桶 = 水桶 + 末影之眼 + 灵感（无序合成）。
- **反应规则**（`fluid/MindFluidReactions`，一张方法内的规则表）：
  水 + 源 → 浓缩灵感结晶，水 + 流动 → 稀释灵感结晶；
  岩浆 + 源 → 思维水晶岩，岩浆 + 流动 → 灵感凝胶。
  只替换思维流体那一格，水与岩浆不受影响，可反复浇液体量产。
- **掉落**：稀释结晶 → 灵感碎片 ×2（时运每级 +0~1）；浓缩结晶 → 灵感 ×1（同样受时运）；
  思维水晶岩 → 思维晶体 ×1（不受时运）；灵感凝胶 → 自身。四种都带精准采集掉落自身。
  三种结晶/岩石需要镐（石镐 / 铁镐分档），凝胶徒手可取。

### 关键结论与踩坑

1. **NeoForge 的 `FluidInteractionRegistry` 覆盖不全**。它沿用原版
   `LiquidBlock#shouldSpreadLiquid` 的方向表 `POSSIBLE_FLOW_DIRECTIONS`
   （DOWN/SOUTH/NORTH/EAST/WEST，内部取 `direction.getOpposite()`），
   实际只检查 **正上方 + 四个水平方向**，不含正下方。
   因此「思维流体正好落在一格水上」时不会判定，会变成思维流体顶掉水。
   最终改为在自定义的 `MindFluidBlock#onPlace` / `#neighborChanged` 里
   自己遍历 `Direction.values()`，六个方向一并检查。
   （`onPlace` 中直接 `setBlock` 替换自己是允许的，原版 `WetSpongeBlock` 就是先例。）
2. **半透明方块用数据生成写 `render_type`，不要用 `ItemBlockRenderTypes.setRenderLayer`**。
   后者自 1.19 起已废弃；正确做法是
   `models().cubeAll(name, tex).renderType("translucent")`，
   生成出的模型 JSON 会带 `"render_type": "minecraft:translucent"`，
   再配 `.noOcclusion()` 属性。`ModelBuilder` 上没有 `ambientOcclusion` 方法。
3. **DeferredHolder 的初始化顺序**：`MindFluidReactions` 里的规则表**不要**在静态字段里
   缓存 `DeferredBlock`（或在静态初始化时调 `.get()`）——该类的加载可能早于方块注册完成，
   会拿到 null。改为在方法内以参数形式传入 `Supplier<? extends Block>`，调用时才解析。
4. **`SlimeBlock` 子类的 codec 无法收窄**：父类返回 `MapCodec<SlimeBlock>`，
   泛型不变型，子类只能返回同样的 `MapCodec<SlimeBlock>`，
   实现写成 `return simpleCodec(InspirationGelBlock::new);`（`simpleCodec` 是 public static）。
5. **带时运的战利品表**：`registries.lookupOrThrow(Registries.ENCHANTMENT).getOrThrow(Enchantments.FORTUNE)`
   拿到 `Holder<Enchantment>`，再交给 `ApplyBonusCount.addUniformBonusCount(...)`；
   外层用 `createSilkTouchDispatchTable` + `applyExplosionDecay` 包住。
   注意 1.21 里常量叫 `Enchantments.FORTUNE`（不是 `BLOCK_FORTUNE`）。
6. 数据生成 `.save(recipeOutput, "名字")` 会把配方写进 **minecraft 命名空间**
   （`ResourceLocation.parse` 默认命名空间）。不传 id 才会按物品注册名落到 `inspiration`。
   项目里已有约 20 个旧配方存在这个问题，本次新增的没再沿用。
7. 贴图生成：`gen_inspiration_crystal_blocks.py` 用 Voronoi 晶面 + 棱线压暗做出结晶感
   （三种模式 facet / gel / rock）；`gen_inspiration_fragments.py` 逐行跨度画不规则碎片并描边。
   本机只有 conda 的 python 带 Pillow，脚本用 `D:/programfiles/conda/python.exe` 跑。

### 验证

- `compileJava` / `runData`（新增 25 个文件）通过。
- 临时自检类挂在 `ServerStartedEvent` 上，七种情况一次性读方块状态：
  水水平+流动 → 稀释灵感结晶；水水平+源 → 浓缩灵感结晶；
  岩浆水平+流动 → 灵感凝胶；岩浆水平+源 → 思维水晶岩；
  **水在正下方+源 → 浓缩灵感结晶**（注册表方案会漏掉的那一种）；
  岩浆在正下方+流动 → 灵感凝胶；无相邻流体+源 → 仍是思维流体方块。
  清理后测试区域确认还原为 `minecraft:air`。
- 服务器日志 `Loaded 1413 recipes`（1412 + 思维流体桶），无解析错误。
- 自检类与端口改动已还原（`run/server.properties` 回到 25565），`run/crash-reports` 已清。

## 翡翠钢工具：灵感系列工具的锻造升级

### 新增内容

- **品质**：`item/tool/ModToolTiers.java`，内含数据驱动的 `SimpleTier` 记录。
  翡翠钢：耐久 2500、挖掘速度 10、攻击加成 3.5、附魔价值 16、
  挖掘等级用 `BlockTags.INCORRECT_FOR_NETHERITE_TOOL`、修复材料翡翠钢锭。
- **工具**：`jade_steel_sword/axe/pickaxe/hoe`，直接复用原有的四个工具类
  （`ExperienceSword` / `StickyAxe` / `ExperiencePickaxe` / `ExperienceHoe`），只换参数。
  经验产出参数化：`ExperienceTool`（动作即产经验）+ `MiningExperienceTool`（挖掘产经验，
  事件处理器只认接口）；`ExperienceDrops` 统一生成经验球。
- **升级模板**：`jade_steel_upgrade_template` 由普通 `Item` 换成
  `item/custom/JadeSteelUpgradeTemplate`（工厂产出 `SmithingTemplateItem`），
  文案结构对齐下界合金模板（沿用原版 `item.minecraft.smithing_template.*` 标题键）。
- **配方**：4 条锻造转换（模板 + 原工具 + 翡翠钢锭 → 翡翠钢工具），写在一处
  `buildJadeSteelUpgrades`。
- **贴图**：`tools/textures/gen_jade_steel_tools.py`（四件工具）、
  `gen_jade_steel_upgrade_template.py`（模板，需把原版材质路径作为命令行参数传入，
  仓库里不留原版素材）。

### 关键结论与踩坑

1. **`Item.Properties#durability` 对 `TieredItem` 无效**。`TieredItem` 构造里会
   `super(properties.durability(tier.getUses()))`，把调用方写的耐久**覆盖掉**。
   实测：`exp_sword` 代码里写 `durability(899)`，游戏内是铁档的 **250**；
   `exp_pickaxe` 写 899，实际是钻石档 **1561**。
   也就是说项目里所有工具/武器的 `.durability(...)` 都是死代码
   （`world_breaker` 宣称 999999，实际 2031）。翡翠钢工具因此不再写 durability，直接吃品质值。
2. **1.21 的「挖掘等级」是反着描述的**：`incorrect_for_<tier>_tool` 标签列出的是
   该档**挖不动**的方块，而 `incorrect_for_diamond_tool` 与 `incorrect_for_netherite_tool`
   在 1.21.1 里都是**空标签**（实测从 client-extra 资源包里读出的 json 为 `{"values": []}`）。
   所以钻石档与下界合金档在掉落判定上等价：换成下界合金标签对原本是铁档的剑/斧/锄是实际提升，
   对本来就是钻石档的镐只是标签变化。
3. **锻造配方仍要显式给 `ResourceLocation`**：`.save(recipeOutput, "名字")` 会落到
   minecraft 命名空间；新配方统一用
   `ResourceLocation.fromNamespaceAndPath(Inspiration.MODID, path)`。
4. **贴图换色要先分类再换色**。直接按亮度重映射会把工具压成灰绿；正确做法是
   保留明度与透明度，只把色相压到目标色相并收缩饱和度
   （`hue=140`、`s=0.30+0.55*原饱和度`、`v*=0.95`），木柄靠色相窗口（20°~45°）与
   中性色靠饱和度阈值（<0.18）排除在外，轮廓与高光因此完全不变。
5. **验证工具的属性只能靠运行时读组件**：`ItemAttributeModifiers`（`ATTACK_DAMAGE` 要 +1、
   `ATTACK_SPEED` 要 +4 才是面板值）、`MAX_DAMAGE`、以及
   `stack.isCorrectToolForDrops(方块状态)`。配方侧用
   `new SmithingRecipeInput(template, base, addition)` 配 `matches` / `assemble`，
   并额外验证底材或材料错误时不匹配。
6. 自检类在 `ServerStartedEvent` 里跑完后直接 `server.halt(false)`，
   `runServer` 任务能自己结束，不必再手动 kill 进程。

## 新增流体提取机与原料精炼机（commit `900afac`）

### 流体提取机（`fluid_extractor`）

- 配方类型 `FluidExtractingRecipe`（**不继承 `InspiredRecipe`**：那个基类产物是 `ItemStack`，
  这里产物是流体），三件套 + `ModRecipes` 注册，JSON 落在 `recipe/fluid_extracting/`。
- 方块实体：单输入槽 + 16,000 mB 输出罐（`Action.DRAIN`，组件名 `fluid_output`）。
  合成走统一 `machine(...)` 形状：翡翠钢 + 下界合金锭 + 强能核心。
- 比例「一锭 = 144 mB」，粒 16、块 1296。目前只有等离子一种流体（PLASMA 没有块/粒形态，
  所以只出了一条配方）。

### 原料精炼机（`raw_refiner`）

- 配方类型 `RefiningRecipe`（**继承 `InspiredRecipe`**，主产物走基类 `result`），
  副产物写成 `List<ItemStack>` 而不是两个字段 —— 空列表表示没有副产物，
  且 6 个字段正好卡在 `StreamCodec.composite` 的上限（写成两个字段就是 7 个，得手写 `of`）。
- 三个输出槽是**同一个库存组件的三个格子，竖排在 x=116**（横向摆会撞到 x=150 的充能罐）。
- 合成 **不走统一形状**：统一形状固定 5/3/1，这里要 3 钙锭 / 5 无恒合金 / 1 高能核心，
  自己写 `SCS / CHC / SSS`。用钙锭是因为**幽匿合金已被结构模拟机占用**。
- 8 条配方：原版三粗矿、粗钫盐/粗铯盐 → 盐、两种盐 → 锭、核废料 → 铀锭 + 镎尘 + 钚尘。

### 回收升级

- 新插件类型 `BYPRODUCT`，**唯一加算**的插件（`byproduct += multiplier - 1`，两个是 ×3 不是 ×4），
  也是唯一只有特定机器读它的插件（只有 `RawRefinerTile` 调 `byproductCount`）。
- 装配配方：思维矩阵锭 + 144 mB 液态等离子 —— 第一份「产物流回装配台」的配方。

## 本轮新坑

1. **罐体设 `Action.DRAIN` 后自身灌入必须 `fillForced`**。普通 `fill` 被动作校验挡掉并静默返回 0，
   表现为「原料被吃掉、罐里一滴都没有」。与 `Action.FILL` 的罐要 `drainForced` 是同一个坑。
2. **`getHandlerFromName` / `serverTick` 在 `ActiveTile` 上，不在 `BasicTile`**。
   自检代码的泛型边界要写 `T extends ActiveTile<T>`，写 `BasicTile<T>` 编译不过。
3. **多输出槽必须先确认所有格子都塞得下再扣材料**，真正写入时留快照、任一格失败整批回滚，
   否则副产物槽满了会吞原料或白送主产物。

### 推送（github.com:443 又 502，走了 REST 兜底）

`api.github.com` 通、`github.com` 不通 → 用脚本把 `origin/master..HEAD` 逐个重放（blob/tree/commit/ref），
三个提交 sha 与本地逐个对齐。脚本在 `%TEMP%/gh_rest_push2.py`。这次踩到两个新的：

1. **`git diff-tree A B` 的 A 是「旧」、B 是「新」**，写反了会把「新增」读成「删除」，
   API 报 422 `GitRPC::BadObjectState`（删一个 base_tree 里本来没有的路径）。
   保险写法是单参数 `git diff-tree --name-status -r <sha>`。
2. **树的 entries 不支持 `encoding: base64`**（只有 `/git/blobs` 支持）。二进制（PNG）
   必须先 `POST /git/blobs` 拿 sha 再在 tree 里引用，否则内联的 base64 会被当文本写坏，
   提交 sha 对不上（表现是「其他文件都对，只有 PNG 变了」）。
3. 另外 `git ls-tree` 默认会给中文路径加引号（`core.quotepath`），比对前加 `-c core.quotepath=false`。

## 修 GUI 容量不同步（BUG）

症状：注入枪装了电容（降级）插件后能量槽上限恒显示 100,000；一般机器装灵感插件后液位画到槽外。

根因：**GUI 画的是客户端 tile 的副本，而 Titanium 不同步容量**——
`EnergyStorageComponent#getContainerAddons` 只注册「存量」一个 DataSlot；
`FluidTankComponent` 只用 `FluidTankReferenceHolder` 同步「流体 id + 存量」
（`ContainerData` index 0/1），容量是构造值，客户端那一份永远是初始值。
所以服务端 `setCapacity` 生效后：能量条 tooltip 上限不变、液位按 `存量/旧容量` 溢出。

修法：`PluginEnergyStorage` 与新建的 `PluginFluidTank` 覆写 `getContainerAddons()`，
在父类同步项之后再挂一个
`IntReferenceHolderAddon(new FunctionReferenceHolder(写容量, 读容量))`；菜单每 tick 广播，
客户端收到写回自己那份缓冲。注意 `FluidTank#setCapacity` 返回 `FluidTank` 而非 void，
子类不能声明成 `void setCapacity(int)`（返回类型冲突），写回时用 lambda 丢掉返回值。

临时自检结果（`runServer`，跑完已删）： fusion `3 slots -> [32000(罐容量), 0, 60000(能量容量)]`；
gun `2 slots -> [0, 67000]`；取下插件后回到 `16000 / 100000`。`runClient` 无崩溃，jar 已重打包。

### 本轮新坑

1. `RegisterDataMapTypesEvent` 是 **IModBusEvent**，订阅类必须 `@EventBusSubscriber(bus = MOD)`。
2. 1.21.1 的注册表常量在 `net.minecraft.core.registries.Registries`（不是 `net.minecraft.core.Registries`）；
   `SectionPos` 也在 `net.minecraft.core`（不是 `world.level`）。
3. **`PlayerEvent.Clone` 构造是 `(新玩家, 旧玩家, wasDeath)` —— 新玩家在前**，传反了会静默得到 0。
4. `RadiationSavedData` 会落盘到 `run/world/data/inspiration_radiation.dat`，
   **上次自检的残留辐射会污染下一次运行**，重跑前先删这个文件。
5. `ServerStartedEvent` 里 forceload 的区块可能还没真正加载，此时放方块/封石会写不进去；
   要延后几刻再布置并 `tracker.refresh()`。
6. 效果必须「先 `removeEffect` 再 `addEffect`」：原版在已有同级/更强效果时忽略新的，降级永远退不回去。
7. attachment 默认不随死亡拷贝，减半逻辑要写在 `PlayerEvent.Clone` 里显式搬运。
8. 区块扫描先看 `PalettedContainer` 的调色板（`getAll`）判断段里有没有登记过的方块，
   没有就整段跳过；逐格前 `hasOnlyAir()` 也先挡一层。

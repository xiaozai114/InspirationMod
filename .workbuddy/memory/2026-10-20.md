## P0 收尾 + P1.1 机器等级化（commit 5184ad2 / e45e830）

### P0 自检"结构永远不成型"是假失败（重要）

没有玩家在线时**服务器只 tick 出生点区块**。自检把结构摆在 `(0,100,0)`，而那个世界出生点是
`(-112,75,-336)` → 5 座结构的 Tile 一个 tick 都没拿到。我白改了 3 版成型判定代码才查明。
正确写法：`level.getSharedSpawnPos()` + `level.setChunkForced(x>>4, z>>4, true)`。
**顺序：先确认 serverTick 有被调用，再看成型结果。**

### P1.1 设计（用户拍板）

- 机器有**等级**属性：普通=1、高能=2，将来 3+；倍率 = **2^(tier-1)**（不是线性）。
- 注册时填：配方类型、等级、槽数；**槽数与等级独立**。
- 每族合并成一个通用 Tile 类（融合/重塑/扭曲/装配），8 个 Tile+Block 类删除，净减 778 行。
- 三处非倍率差异**全部保留原行为**（装配台两种 GUI 布局、重塑机进度条颜色、扭曲机时运）。

### 三个必读的坑

1. `createEnergyStorage()` 在 **PoweredTile 构造期**就被调用（javap 字节码第 16 行），
   子类字段全是 null → 容量只能按 tier 1 基准建，之后补正。
2. 补正 `applyTier()` 必须放在**构造体最后一行**。放 super() 之后立刻调会 NPE
   （`chargeTank` 是本类后面才建的字段）——自检抓到的真实 bug，放机器即崩服。
3. **Titanium `@Save` 不认 List**：处理器只有 BlockPos/数值/枚举/ItemStack/Tank/INBTSerializable。
   装配台可变数量流体罐改成手写 saveAdditional/loadAdditional。

## 第二台机器：物质重塑机（Matter Reshaper）

- 新增物品 4 个：`powerful_core`（强能核心）、`high_energy_core_base`（高能核心基底）、
  `jade_steel_upgrade_template`（翡翠钢升级模板）、`basalt_alloy_firestriker`（玄武岩合金打火石）。
  打火石用 `item/custom/BasaltAlloyFirestriker`（继承 `FlintAndSteelItem`）+ `durability(0)`
  实现「不可破坏」——最大耐久为 0 时 `ItemStack#isDamageableItem()` 为假，`hurtAndBreak` 直接返回。
- 新增配方类型 `reshaping`（物质重塑），`machine/recipe/ReshapingRecipe{,Input,Serializer}`：
  主输入必填 + 辅助材料可选，**按槽位固定匹配**（不做顺序交换），默认 300t / 120FE·t。
- 机器实现拆成三个文件，避免逻辑堆在一起：
  - `machine/blockentity/ReshaperTask.java`——一次待执行的重塑任务
  - `machine/blockentity/ReshaperTaskResolver.java`——先查 reshaping，再回落到右键转化配方
  - `machine/blockentity/MatterReshaperMachineTile.java`——组件与 tick 逻辑
- 机器参数（对比物质融合器的 60k FE / 1000 FE·t / 200t / 40FE·t）：
  200k FE 缓冲、4000 FE/t 输入上限；右键转化配方在重塑机中统一按 400t / 200FE·t 执行（更慢更耗电）。
- 新增 `util/BlockItemLookup`：方块 → 代表物品（流体方块退回桶），机器与 JEI 共用同一份实现；
  `RightClickBlockRecipe` 增加 `matchesStacks` / `displayResult` 供机器与 JEI 复用。
- 合成配方：
  - 强能核心 = 4 铯锭（四角）+ 4 玄武岩合金（四边）+ 1 强化核心（中心）
  - 物质重塑机 = `JJJ / RCR / JRJ`（J 翡翠钢锭 ×5、R 红石锭块 ×3、C 强能核心）
- 重塑配方（数据生成，`data/inspiration/recipe/reshaping/`）：
  - 任意 `#minecraft:trim_templates` → 翡翠钢升级模板（400t / 200FE·t）
  - 强能核心 → 高能核心基底（600t / 400FE·t）
  - 打火石 + 玄武岩合金 → 玄武岩合金打火石（400t / 200FE·t）
  - 装备回炉 `reshaping/recycling/*`：皮革/铁/金/钻石/下界合金 × 四件套与五种工具
    （+ 海龟壳），共 41 条，按原版合成消耗返还材料，160t / 60FE·t
- JEI 新增 `ReshapingRecipeCategory`（绿色箭头背景 `reshaping.png`）；物质重塑机同时登记为
  `reshaping` 与 `right_click_block` 两个分类的催化剂。
- 验证：`compileJava` / `runData` 通过；`runServer` 日志 `Loaded 1392 recipes`
  （1346 + 强能核心 1 + 重塑机 1 + 重塑配方 44），`Done (5.083s)`，无解析错误。
- 复用的做法：数据生成里把机器方块状态抽成 `machineBlock(BlockWithTile)`，

## 第三台机器：矿物扭曲机（Mineral Twister）+ 三条重塑配方

- `ReshapingRecipe` 增加可选字段 `input_count`（默认 1）：表达「3 个红石 → 1 个红石锭」这类
  需要堆叠数量的转化。配套改动：序列化器加一段 VAR_INT；`ReshaperTask` 加 `firstInputCount`；
  **重要**：`MatterReshaperMachineTile#canProcess` 必须校验槽内数量是否够一次扣完，
  否则材料不足时会扣 1 个却产出整份产物。
- 新增三条重塑配方（`data/inspiration/recipe/reshaping/`，200t / 80FE·t）：
  1 煤炭 → 2 褐煤，3 红石 → 1 红石锭，3 青金石 → 1 青金石锭。

  单输入矿石 + 基准产物，字段 `fortune_level`（默认 6）、`duration`（默认 400）、`energy_per_tick`（默认 300）。
- `util/OreFortuneBonus`：独立实现原版 `minecraft:ore_drops` 公式

- `machine/blockentity/MineralTwisterTile.java`：单输入 + 单输出 + 进度条，400k FE / 8000 FE·t；

- 机器合成：`JJJ / LCL / JLJ`（J 翡翠钢锭 ×5、L 青金石锭块 ×3、C 强能核心）——与重塑机同构，
  只把红石锭块换成青金石锭块。
- 扭曲配方（`data/inspiration/recipe/twisting/`，共 11 条）：煤/铁/铜/金/红石/青金石/钻石/绿宝石/
  下界金/下界石英/铯盐矿 → 对应粗矿或原版产物。基准产量：红石与青金石各 4（原版下限），
  下界金 2 个金粒，其余 1。档位：普通矿 400t/300FE·t，稀有矿（金/钻石/绿宝石/下界金）600t/400FE·t。
  远古残骸（原版不受时运影响）与无恒矿石（直接掉无恒物质、价值高）**未纳入**。
- JEI 新增 `TwistingRecipeCategory`（背景 `gui/jei/twisting.png`），底部两行文字展示
  「等效时运 6：产量 1~7，期望 3.6」与耗时/能耗；重塑机分类的输入槽也会按 `input_count` 显示数量。
- 贴图新增生成脚本目录 `tools/textures/`（一个文件一个用途，路径相对仓库根，不含绝对路径）：

## 机器插件系统 + 等离子锭 + 第四台机器：灵感装配台

- **贴图**：`tools/textures/gen_ingot_textures.py`（新）以 `jade_steel_ingot.png` 为模板，
  按亮度排序把色阶映射到目标调色板，生成 `plasma_ingot`（天蓝 `#145E8C` → `#9BF2FF`）
  与 `basalt_alloy`（玄武岩灰 `#111317` → `#767C88`），因此三者的锭形轮廓完全一致。
  玄武岩合金只换贴图，融合配方（玄武岩 + 远古残骸 → 2）不动。
- **插件系统**（`machine/plugin/` 三个文件，一个文件一个职责）：
  - `MachinePluginType`：`ENERGY_CAPACITY` / `CHARGE_CAPACITY` / `SPEED`，倍率常量 `MULTIPLIER = 2`；
    顺带实现 Titanium 的 `IAugmentType` 以便将来并入原版 augment 体系。
  - `PluginEffects`：record，把已装插件折算成 `speed` / `energyUse` / `chargeUse` /
    `energyCapacity` / `chargeCapacity`。约定 **`energyUse = speed²`**、**`chargeUse = speed`**，
    于是速度插件「快 2 倍」自然对应「每刻耗电 ×4、每刻充能 ×2」。
  - `PluginEnergyStorage`：Titanium 的 `EnergyStorageComponent` 没有容量 setter，
    只能写 protected 字段 `capacity`，并在缩小容量时把多余能量截断。
- `item/custom/MachinePluginItem`：`stacksTo(1)`、`Rarity.UNCOMMON`，
  `appendHoverText` 输出「装入机器插件槽」+ 该类型的效果说明 + 倍率，效果写在物品描述里。
- `machine/blockentity/InspiredMachineTile` 重写为「消耗充能 **且** 接受插件」的机器基类：
  - 复用 Titanium 自带的 **四个 augment 槽**（就是玩家在机器界面右侧看到的四个空槽）
    作为插件槽——构造时用 `getAugmentInventory().setInputFilter(...)` 把过滤条件换成
    `stack.getItem() instanceof MachinePluginItem`，不需要新开 GUI 槽位。
  - 每刻算一个「插件内容指纹」（`pluginStamp`），变了才重算，避免每刻遍历。
    `applyPlugins()` 里调 `PluginEnergyStorage#setCapacity`、`setChargeCapacity`、
    `getProgressBar().setProgressIncrease(...)`；容量被取下而变小时超出的部分会被截断。
  - 新增 `protected abstract ProgressBarComponent<T> getProgressBar()` 与 `baseEnergyCapacity()`。
    **踩坑**：三台已有机器本身就有 `public ProgressBarComponent getProgressBar()`，
    再加一份抽象声明会撞名，正确做法是给已有的那个方法加 `@Override`，而不是另写一份。
- **新增物品**：`plasma_ingot`（等离子锭）、`capacitor_plugin` / `inspiration_plugin` / `speed_plugin`。
  外形来自 `tools/textures/gen_plugin_textures.py`（16×16 底板上叠闪电 / 星形 / 双箭头，黄 / 紫 / 青）。
- **新配方类型 `assembling`（灵感装配）**：
  - `machine/recipe/AssemblingRecipe{,Input,Serializer}`：1~4 条物品原料 + 可选
    `FluidIngredient` + `fluid_amount`，默认 300 刻 / 200 FE·t。
  - 原料匹配用**回溯法**（`resolveSlots`）做「材料 ↔ 槽位」的指派，因此玩家不必按固定顺序摆料；
    返回 `int[]` 槽位映射或 null。
  - 流体输入槽与灵感充能罐是**两个独立槽**：坦克用
    `stack -> !InspirationCharge.isChargeFluid(stack)` 作校验，机器消耗时一律用 `drainForced`
    （该罐只进不出），效果上接近 GregTech 的组装机。

## 虚空能量体系：第一阶段（团簇与供能）

用户一次性给了一整条产线（钻头 → 开裂基岩 → 提取器 → 团簇 → 虚空注入 → 凝聚器 → 零点发电机）。
量级很大，先按 4 个问题把底层定死，再分阶段实现。

### 已确定的四个底层决策

| 问题 | 结论 |
| --- | --- |
| 128 GFE 超出 int | 发电机用 **long** 自建能量缓冲，自己画能量条；对外仍给 int 接口 |
| 团簇的载体 | **实体**（无碰撞、发光面片、右键查询） |
| 虚空注入枪 | **新方块**，放进现有注入结构里替换普通注入枪 |
| 64 个增幅器 | **单槽、按 64 堆叠** |
| 10% 扣量 | `cost = max(1, ve/10)`，拿 **cost** 比 [min,max] |
| 中继器 | 必须与团簇**同格**，以自身为中心 ±2（5×5×5） |
| 团簇消失 | 能量归零后持续 200 刻消散 |

### 虚空注入枪放置即崩（已修）

- 症状：放下方块抛 `IllegalStateException: Invalid block entity inspiration:injection_gun //
  VoidInjectionGunTile ... got Block{inspiration:void_injection_gun}`。
- 原因：`InjectionGunTile` 的构造器**把类型写死了** ——`super(INJECTION_GUN.getBlock(),
  INJECTION_GUN.type().get(), pos, state)`。子类继承时实体声明的仍是注入枪类型，
  与方块注册出来的 BE 类型对不上，`BlockEntityType` 校验直接拒收。
- 修法：加一个 `protected InjectionGunTile(block, type, pos, state)` 重载，公开构造器委托给它；
  `VoidInjectionGunTile` 传 `VOID_INJECTION_GUN` 的方块与类型。
- ⚠️ 教训：**Titanium 的每个机器 Tile 构造器都应允许传自己的 block/type**，
  否则任何「block 复用 + tile 子类」的写法都会在放置时炸。

### 压缩红石锭 / 光谱合金 / 高能物质融合器

- `FusionRecipe` 支持**第四种材料**：codec 加 `fourth_input`/`fourth_count`，`ingredients()`/`counts()`
  按「有第四项 → 有第三项 → 两项」补齐；序列化器跟着加。匹配逻辑本来就走 `resolveSlots`，
  所以四槽机器不需要改匹配代码。
- `MachineSpec.of(3, 4)` = 等级 3、四输入槽；高能物质融合器复用 `MatterFusionMachineBlock`，
  属性按 2^(3-1)=×4 于一级。
- 压缩红石锭：注能红石锭 + 铀锭，注入 2 级、窗口 1M~2M FE（注能红石块**不存在**，
  材料 `ENERGIZED_REDSTONE` 没开 block，所以底材用的锭）。
- 光谱合金：`ModMaterials` 新条目，`.radiation(1)`、`.itemId("spectrum_alloy")`；
  配方是四材料融合（镍 + 钍 + 虚空露珠 + 思维矩阵），只有四槽机能跑。
- 贴图：两种锭加了 `gen_ingot_textures` 调色板；高能融合器的三面是把强能版提亮 + 偏紫。

# 2026-10-19

## 定位「IDEA 运行键一跑就卡在 Calculating task graph」的真凶

### 结论

**不是配置缓存的锅，是 Gradle 在配置阶段偷偷联网，而那个域名连不上。**

对卡住的 daemon（pid 51172）抓了线程栈（`jstack` → `%TEMP%\gd51172.txt`），
`Daemon worker` 线程停在：

```
sun.nio.ch.NioSocketImpl.timedFinishConnect   ← TCP 握手，一直没回包
  org.apache.http...SSLConnectionSocketFactory.connectSocket
  org.gradle.internal.resource.transport.http.HttpResourceAccessor.getMetaData
  ...DefaultExternalResourceArtifactResolver.downloadStaticResource  (拿一个 .pom)
  ...TaskNodeCodec.writeTask → FileCollectionCodec                   ← 写配置缓存时序列化 classpath
```

即：**把任务图写进配置缓存时要解析 classpath 的文件集合**，解析就要去仓库 HEAD 一个 pom，
而那个仓库连不上 → **没有任何输出地一直等**（Gradle 默认没有连接超时）。

再 `Get-NetTCPConnection -OwningProcess 51172` → `SynSent 199.59.149.236:443`；
`nslookup maven.neoforged.net` → 正是 **199.59.149.236**。

### 连通性实测（本机）

| 目标 | 直连 | 走 127.0.0.1:2673 代理 |
|---|---|---|
| repo1.maven.org | 200 | 200 |
| maven.aliyun.com | 404(可达) | 404 |
| maven.firstdark.dev | — | 404(可达) |
| **maven.neoforged.net** | **连接超时** | **502/超时** |

→ NeoForge 的 maven 现在从这台机器**彻底不通**，在线构建必然卡死或失败。
注意 Gradle **不认** `http_proxy` 环境变量（它要 `systemProp.https.proxyHost`），
而这个代理对 neoforge 也返回 502，所以配代理也没用。

### 关键认知：配置缓存是按「任务集」分别存条目的

昨天我跑 `help` 存下的条目**只对 help 有用**。用户跑 `runClient` 是另一套任务图，
要重新序列化 → 重新解析全部 classpath → 又去联网。
所以「我这边跑通了、用户那边还卡」就是这个原因。
**每个常用的任务集（runClient / build / runData）都得各自成功写一次条目。**

### 已做的修改（gradle.properties）

1. `org.gradle.java.home=C:\\Program Files\\Java\\jdk-21`
   —— 命令行原本走 JAVA_HOME（D:\1 = Java 25）、IDEA 走 jdk-21，两套 daemon 各自冷启动。
   改完后日志里 daemon 的 javaHome 已统一为 jdk-21。
2. 网络超时（**治「无声卡死」，很值**）：
   ```
   systemProp.org.gradle.internal.http.connectionTimeout=15000
   systemProp.org.gradle.internal.http.socketTimeout=30000
   ```
   实测生效：原来无限等待，现在 15s 超时，整体约 1 分钟报错退出并给出明确原因
   （`Connect to maven.neoforged.net:443 ... failed: Connect timed out`）。

### 试过并已回退的方案（别再试）

给 MDG 自动加的 `maven.neoforged.net` 仓库加
`content { includeGroupByRegex 'net\\.neoforged.*' }`，想让它别被第三方依赖 probe。
结果：**改仓库配置会让已缓存的解析结果失效**，离线连 parchment 都解析不了
（`No cached version of org.parchmentmc.data:parchment-1.21.1:2024.11.17`，
虽然 zip 明明在 `files-2.1` 里）。回退后立刻恢复。
—— 教训：**动仓库的 content / metadataSources 会连带废掉离线缓存**，代价远大于收益。
而且就算过滤了，MDG 自己还要 `net.neoforged:neoform-runtime` 的 `.module`，照样不通。

### 最终解法：日常一律 `--offline`

全部依赖（含 MBD2 / LDLib2 / parchment / neoforge）都已在缓存里，离线完全够用：

- `./gradlew --offline runClient --dry-run` → BUILD SUCCESSFUL 8s，`Configuration cache entry reused.`
- `./gradlew --offline build --dry-run`     → BUILD SUCCESSFUL 15s，`entry stored.`

**IDEA 侧**：运行配置（Gradle 类型）的 **Arguments** 填 `--offline --console=plain`；
`--console=plain` 才能在 Run 窗口里看到一行行的 `> Task :xxx` 进度。
MDG 自动生成的运行配置可能在同步后被覆盖，**建议自己新建一个 Gradle 运行配置**
（Tasks: runClient，Arguments: `--offline --console=plain`），不会被覆盖。

已验证 `-Dorg.gradle.offline=true` **不被识别**（照样联网超时），没有全局开关，
只能显式 `--offline`。

8. 死代码：`control/VecHelper` 355 行（30 个方法只有 1 个在用，且 import 了客户端类）、
   `ModFuelItem`、`ModItemTagsProvider` 空实现、`ModBlocks.FLUID_BLOCKS` 死寄存器、

### 排查手法沉淀

1. 卡住时先 `Get-NetTCPConnection -OwningProcess <pid>` → 看是不是卡在 SynSent 的远程 IP。
2. `jstack <pid>` 看 `Daemon worker` 线程停在哪（CPU 几乎不涨 = 在等 IO，不是在算）。
3. daemon 日志看**最后几行**，中断/被杀的原因都写在那里。

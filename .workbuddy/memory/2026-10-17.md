## 发电机器（碱性反应堆 / RTG 发电机）+ 碱性值 + 机器 tooltip

- **碱性值体系**（新包 `alkali/`）：`AlkalinityDataMaps`（`inspiration:alkalinity`，synced）、
  `Alkalinity#of`、`client/AlkalinityTooltips`（名字下面一行「碱性值：x」）、
  `data_maps/item/alkalinity.json`（钙粉 1 / 铯粉·铯锭 4 / 钫粉·钫锭 6，口径对齐 `AlkaliItem` 爆炸半径）。

- **发电机基类** `machine/blockentity/PowerGeneratorTile`：继承 Titanium `MachineTile`

  每刻 `pushEnergy` 推六邻。子类只答 `isFuel/fuelValue/burnTicks/energyPerTick/baseEnergyCapacity/baseMaxExtract`，
  另有 `onBurnComplete` / `onGenerationMinute` / `canAcceptResult` 三个钩子。
- **碱性反应堆**（`alkaline_reactor`）：12,000 刻、100×碱性值 FE/t、无副产物；缓冲 1M、输出 8k。
- **RTG 发电机**（`rtg_generator`）：24,000 刻、1000×辐射值 FE/t；缓冲 4M、输出 64k；
  每分钟释放 `(x-1)^3` 点区块辐射，x>9 时按 `(x-9)/1000` 概率爆炸（威力 6，TNT 交互）；
  烧完吐 x 个核废料（输出槽预留判定在开工前）。
- **合成**：碱性反应堆 = 5 翡翠钢 + 3 红石锭 + 发电核心；RTG = 5 无恒合金 + 3 注能红石锭 + 反应核心
  （都走 `machine(...)` 的统一形状，X 位填主要材料）。
- **机器 tooltip**：`machine/client/MachineTooltips` 按物品 ID 匹配 11 台机器，
  键 `tooltip.inspiration.machine.<名>`，加工类写配方类型、发电类写发电机制。
- **`machine/client/FacingLabels`**：把「按组件挂按钮标签」抽成静态工具，两条继承链共用。
- **贴图**：`tools/textures/gen_generator_cores.py`（前两张是已有核心转色相，`saturation<0.25` 的金属不动；
  核废料是椭圆裁形 + 角度扰动半径 + 绿色裂纹）、`tools/textures/gen_generator_blocks.py`
  （表驱动，青绿反应腔 / 暗红同心方框）。

### 踩坑（重要）

1. **燃料在开工瞬间就扣掉** → `canIncrease` 若仍然查槽位，进度条会立刻冻在第一格（实测只发了一刻的电）。
   `canBurn` 必须先认 `burningValue`，归零才回查槽位。
2. **`MultiProgressBarHandler` 的 else 分支**：`canIncrease` 为假且 `canReset` 为真时，它把进度条
   `setProgress(increaseType ? 0 : max)` 但**不调用 `onFinishWork`** —— 缓冲满时核废料会丢。
   因此烧完改用自己数的 `burnedTicks` 判定，`finishBurn()` 写成可重入（强度归零即返回）。
3. Titanium 的 `GeneratorTile` 不能直接用：`canIncrease = canStart() && progress==0` 与 `setIncreaseType(false)`
   组合起来，第二刻起 `canIncrease` 恒假，进度条再也不会动（jar 里也没有它的任何子类）。
4. 私有字段在 lambda 里通过类型变量 `T` 访问会报「private 访问控制」，要转成 `PowerGeneratorTile<?>` 或封装成方法。

- 两台都只收对应燃料（钻石被 `isItemValid` 拒）；`Loaded 1636 recipes`（原 1632，新增 4 条）。
- 自检残留：删了 `run/world/data/inspiration_radiation.dat`（本次自检写出的 160 点）。

## 机器 tooltip 改成用户风格 + 两台发电机改名

用户给了三条样板（碱性发电机 / 物质融合机 / 地核钻探者），要求照风格补齐剩下 8 条：

- **`MachineTooltips` 支持多行**：一个键写完整段文字，语言值里用 `\n` 分隔，取到字符串后
  `split("\n")` 逐行挂（Minecraft 不会自己把语言值里的换行折行，必须手动切）。
- **风格**：加工类首行固定「配方类型：xxx」，上位机再补一行差异（速度 ×2、槽位数）；
  发电类是「投入……发电。」→「发电量：100x/tick；燃烧时间：12000tick。」→「x为物品碱性值」，
  副作用与副产物各占一行。发电量里 tick 用英文小写、数值不带空格（照抄用户写法）。
- **改名**：`alkaline_reactor` 显示名 → **碱性发电机**（En: Alkaline Generator），
  `rtg_generator` → **RTG反应堆**（En: RTG Reactor）。**内部 ID 与语言键都不动**
  （`tooltip.inspiration.machine.alkaline_reactor` 仍是 reactor）。
  已批量同步 12 个文件的中文注释与 README。

## 结构模拟机（第一台多方块）+ 高能机器外壳

用户要一整套新内容：淡紫铁块外壳、4×3×3 中空多方块、五种仓室、结构数据与沉船模拟，
并提示「找一下网上有什么库提供了多方块结构的功能」。

### 选型：只借 Multiblocked2 的结构层

1.21.1 上唯一成熟的多方块库是 **MBD2 21.1.1（+ LDLib2 2.2.39.a）**，但 21.1.1 已经是
「定义 + 蓝图 + 状态机」的完整机器框架：实现 `IMultiController` 就**连带**要写整套 `IMachine`
（`getRecipeLogic` / `getFrontFacing` / capability holder……），与「UI、能量、充能留在 Titanium」冲突。
最终方案：**控制器不实现接口**，只用 `FactoryBlockPattern` / `Predicates` / `MultiblockState`，
成型靠 `BlockPattern#checkPatternAtWithoutController(state, facing)` + 自遍历四个水平朝向。
两个库都 `implementation` 且**禁止 shade / jar-in-jar**，在 `neoforge.mods.toml` 里声明 `required`。

### 结构层要点（都是踩过的）

- `FactoryBlockPattern.start()` 的相对方向是 `{LEFT, UP, FRONT}`；`aisle(String...)` 的
  **第一个字符串是最低那行**（`stringDir=UP`），而 `aisle()` 调用顺序沿 `FRONT` 递增。
- `checkPatternAt` 里 `x = a - centerOffset[0]`、`y = b - centerOffset[1]`、`z = c - centerOffset[2]`，
  `centerOffset` 就是主方块那格在图案里的下标。客户端虚影要摆得和成型一致，必须照抄
  `setActualRelativeOffset` 那套公式（`SimulatorPattern#rotate`）。
- 成型形状：`SHAPE[层][行]`，层自后往前，行自下而上；主方块在**正面中层左二**（`c=2, b=1, a=1`）。
  空腔 2 格正好是 4×3×3 的内部，所以它确实是「中空长方体」。
- `Predicates.air()` 要求真空气；外壳与五种仓室用一个 `Predicates.custom` 谓词一起吃下。

### 踩到的两个 Titanium 参数顺序坑

- `FluidTankComponent(name, **capacity**, x, y)` —— 容量在**第 2 位**（与 `SidedFluidTankComponent` 同一套）。
  一开始写成 `(name, 44, 20, CAPACITY)`，结果罐子容量变成 44 mB，自检里表现为「充能只有 4」。
- `InventoryComponent(name, x, y, slots)` 反过来是 slots 在最后；`EnergyStorageComponent(capacity,
  maxReceive, maxExtract, x, y)`。三者顺序**互不相同**，只能逐个 javap 确认。

### 其余实现要点

- 五种仓室共用 `HatchBlock<T>`，方块实体按需要的基类各走一条：
  要界面 → `HatchTile extends ActiveTile`（只有它带 `openGui`）；
  能量端口 → `PoweredTile`；灵感提供仓 → `ActiveTile`（罐子靠管道灌，无界面）。
- 数据**不消耗**：每个进度周期重读数据仓槽位，取出来就停机；`spec.duration()` 变化时同步
  `progressBar.setMaxProgress`。跑完 `rollLoot` 用 `LootContextParamSets.CHEST` + 随机挑一张表，
  产物先进 `pendingOutput` 再逐刻往输出仓倒。
- **用户指定「目前不能装插件」**：电与充能来自仓室，插件改容量没意义 → augment 槽空置。
- 状态用 `SimulatorStatus` 枚举，**枚举顺序即优先级**；`@Save int status` + `markForUpdate` 推客户端，
  `StatusAddon` 在界面 `(8,90)` 画一行。
- 客户端虚影：`SimulatorPreviewRenderer` 在 `AFTER_TRANSLUCENT_BLOCKS` 用**独立的**
  `MultiBufferSource.immediate(ByteBufferBuilder)` 画（不动共享缓冲，否则 `endBatch()` 会提前冲掉别人的批次），
  每格缩到 0.8（照 MBD2 的做法），朝向取玩家水平朝向。
- `AssemblingRecipe` 加了 `counts`（每种材料消耗几个）与流体支持 —— 沉船数据要 64 木板 + 4B 水。

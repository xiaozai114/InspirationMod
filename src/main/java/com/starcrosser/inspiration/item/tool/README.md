# 工具与武器（`item/tool` 包）

相关：[升级模板来自物质重塑机](../../machine/README.md) ・ [注能材料来自注入合成](../../injection/README.md) ・

## 三条升级链

```
灵感系列（5 件：剑 / 镐 / 斧 / 锄 / 铲）
   └─ 翡翠钢升级模板 + 翡翠钢锭 ──► 翡翠钢系列
          └─ 注能翡翠钢升级模板 + 注能翡翠钢 ──► 注能翡翠钢系列
```

- **翡翠钢升级模板**由物质重塑机从任意盔甲纹饰模板重塑得到（400 刻 / 200 FE·t⁻¹）。
- **注能翡翠钢升级模板**要把它放进物质束缚器，用注能翡翠钢做**二级注入**（500k~1M FE），
  底座必须是幽匿合金块；注能翡翠钢本身是翡翠钢锭的一级注入产物。
  两个模板的文案结构都与下界合金升级模板一致，由 `JadeSteelUpgradeTemplate` 的两个工厂产出，
  差别只在语言键前缀、适用范围（注能版多一把铲）与图标配色。

### 挖掘等级

翡翠钢与注能两档统一取下界合金档（`incorrect_for_netherite_tool`），即能挖掉全部需要钻石镐的方块
—— 对原本是铁档的剑、斧、锄、铲是实际提升，镐原本就是钻石档，只是品质标签升级。
注意**挖掘等级与耐久是两回事**：灵感之镐用钻石品质但不代表耐久也得跟钻石一样。

## 耐久

原版是「同一品质共用一份耐久」（钻石全套 1,561、下界合金全套 2,031），因为
`TieredItem` 的构造里有一句 `properties.durability(tier.getUses())`，会把
`Item.Properties#durability` 设的值**覆盖掉**。本模组想让每件装备各有各的耐久。

**完全不用 `TieredItem` 是可行的，但代价不在它身上**：1.21 的挖掘等级与速度全由
`DataComponents.TOOL` 组件驱动，`DiggerItem` / `SwordItem` 本体各自只有几十行；
真正麻烦的是下面那些 `useOn` —— `ShovelItem` 压土径、`HoeItem` 耕地、
`AxeItem` 剥皮 / 刮铜 / 脱蜡，而我们正好依赖这三样。照抄约 350 行、抄漏一处就静默丢功能。

所以改用**品质包装**：`DurabilityTier` 把原品质包一层，只把 `getUses()` 换成指定值，
挖掘速度、伤害加成、挖掘等级、附魔价值、修复材料全部代理给原品质。
这样 `TieredItem` 写进 `MAX_DAMAGE` 组件的就是我们要的数（组件值与 `getMaxDamage()` 一致，
自检逐件核对过）。用法：

```java
new ExperienceSword(ModToolTiers.withDurability(Tiers.IRON, ToolDurability.EXP_SWORD), ...)
```

- `ModToolTiers#withDurability(Tier, int)` —— 包一层，能用原版 `Tiers` 也能用自定义品质。
- `ToolDurability` —— 每件装备的耐久常量集中在这里。

数值规则：**每档基數 × 类型系数**（剑 0.9 / 斧 1.0 / 镐 1.1 / 铲 1.1 / 锄 1.25）——
剑最少、斧次之、镐与铲居中、锄最多（用途最窄，给高点作为补偿）。
基数：灵感档 800、钻石档特殊武器 1,800、翡翠钢 2,500、注能 4,000。

## 特殊效果

两个系列各自保留灵感系列的特殊效果，并按新数值放大：

- 剑命中掉经验、镐挖方块掉经验、斧剥皮掉木棍与经验、锄草方块掉草皮与经验；
- **铲把草方块压成土径时**掉草皮与经验（`ExperienceShovel`，只在 `GRASS_BLOCK` 且原版逻辑
  真的压成功时才触发 —— 判据是 `result.consumesAction()`，泥土、菌丝体等其它可压方块不掉）。

经验量由 `ExperienceTool` / `MiningExperienceTool` 两个接口暴露，挖掘事件只认接口不认物品。

### 蓄力增益（仅注能系列）

`ChargedBuffTool` 接口声明 `chargedEffect()`，其余参数（蓄力 30 刻 / 消耗 20 点经验 /
持续 600 刻 / I 级）都是默认值；`ChargedBuff` 是共同实现：

1. `use`：经验不足（按 **`totalExperience` 总点数**，不是等级）直接 `FAIL`，连蓄力都不让开始；
2. `onUseTick`：客户端每 5 刻冒一圈附魔粒子；
3. `finishUsingItem`：扣 `giveExperiencePoints(-20)`、上效果、播紫水晶叮声。中途松手不会走到这里。

**接口的 `default` 方法打不过父类 `Item` 的 `use`** —— 五件工具都必须自己覆写
`use` / `getUseDuration` / `onUseTick` / `finishUsingItem` / `appendHoverText` 并转调 `ChargedBuff`。

## 实现要点

品质定义集中在 `item/tool/ModToolTiers.java`（`SimpleTier` 记录，数据驱动），
耐久单独放在 `ToolDurability.java`，包装实现是 `DurabilityTier.java`。
两个易踩的点：

- `Item.Properties#durability` 对 `TieredItem` **无效**：`TieredItem` 构造会用
  `properties.durability(tier.getUses())` 覆盖（`durability()` 本身就是往组件里写
  `MAX_DAMAGE`，后写的赢）。要按件给耐久就走 `ModToolTiers#withDurability`，见《耐久》。
  不在 `TieredItem` 体系里的物品（打火石、钻头、盾牌）写 `durability()` 照常生效；
  想做「不可破坏」用 `durability(0)`（此时 `isDamageableItem()` 为假）。
- 1.21 的挖掘等级由 `incorrect_for_<tier>_tool` 标签反着描述，而 diamond 与 netherite
  两个标签**都是空的**，两者等价。

核对工具真实数值要读组件：`ATTACK_DAMAGE` +1、`ATTACK_SPEED` +4 才是面板值，另看 `MAX_DAMAGE`；
挖掘等级用 `stack.isCorrectToolForDrops(state)`（剑恒为 false，别误判）。
自检里改经验**要调 `giveExperiencePoints`**，直接写 `player.totalExperience` 会让原版的
经验进度循环在扣费时把总量归零，读出假数据。

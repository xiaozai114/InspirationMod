# 注入合成（`injection` 包）

相关：[配方](../recipe/README.md) ・ [注入枪插件槽](../machine/plugin/README.md)。
结构本身不耗电、不耗充能，**执行成本全部由注入枪储存的 FE 承担**。入口 `ModInjection`。

## 结构

| 位置 | 方块 | 说明 |
| --- | --- | --- |
| 中心 | 物质束缚器 | 8 等离子锭 + 1 不稳核心；单槽限量 1，产物回同一槽；物质悬浮自转在台面之上 |
| 正下方 | 底座方块 | 用方块标签 `inspiration:injection_tier_N` 声明等级（玄武岩合金块 1 级、幽匿合金块 2 级） |
| 5×5×5 内 | 注入枪 | 发射器 + 4 翡翠钢锭；只进不出，容量 100,000 FE，最大输入 20,000 FE·t⁻¹；右侧四个插件槽 |

`InjectionStructure` 判定：底座在束缚器正下方 1 格，注入枪按切比雪夫距离 ≤ 2。
加新等级只需给方块打标签，代码不用改（标签与等级换算在 `InjectionTiers`）。
两个方块都是不完整方块，碰撞盒（`getBoundingBoxes` + `hasCustomBoxes`）与模型元素严格对应。

## 取放物质

| 操作 | 行为 |
| --- | --- |
| 右键（手持有物、槽空） | 放入一份 |
| 右键（空手、槽有物） | 取回手上 |
| 右键（手持有物、槽有物） | 取回背包 |
| **潜行**右键 | 打开界面 |

⚠️ 取放分支**必须返回 `ItemInteractionResult.CONSUME`**（返回 PASS 会继续走 `useWithoutItem`
把同一段逻辑再执行一遍）。`MatterBinderBlock` 的处理顺序是「绑定器 → 潜行开界面 → 取放」。
承放的物质由 `client/renderer/MatterBinderRenderer` 画在台面上方（绕竖轴自转 + 上下浮动）。

## 绑定与触发

绑定器（2 翡翠钢锭 + 末影之眼）右键束缚器记坐标，再右键注入枪绑定，潜行右键解除；
关系存在物品的 CustomData（`BinderPos`）。绑定后枪的 `LINKED` 状态置位（换接线贴图），
并**自动把枪口转向束缚器**（六向都支持，取差值最大的轴），每刻校正一次；
超范围或束缚器被拆则绑定失效。

红石**上升沿**触发一次注入，且**只有被触发的那一支枪放电** —— 玩家靠「给哪支枪脉冲」
决定这次投入多少能量，同结构其它枪不受影响。

## 判定

启动瞬间清空枪内存量并立即扣基底与注入物质，再按配方窗口 `[min, max]` 判定：

| 放电量 | 结果 |
| --- | --- |
| 低于 `min_energy` | 不产出，材料已扣（损失） |
| 窗口内 | 成功，产物写入束缚器槽位 |
| 高于 `max_energy` | 在束缚器处爆炸（半径 3） |

过程 8 刻，期间播放 `InjectionBeam` 激光粒子。**爆炸风险是设计的一部分，不要加保护**，
也别把「先扣材料」改成「先判定再扣」。

| 红石锭 | 灵感 | 1 | 150k ~ 300k | 注能红石锭 |
| 青金石锭 | 灵感 | 1 | 10k ~ 15k | 注能青金石锭 |
| 等离子锭 | 灵感 | 1 | 1M ~ 2M | 注能等离子锭 |
| 盾牌 | 末地合金 | 1 | 500k ~ 1.5M | 末地合金盾牌 |
| 末地合金 | 无恒物质 | 1 | **种子随机** | 无恒合金 |
| 铁锭 | 铯锭 | 1 | 150k ~ 250k | 盖革计数器 |
| 翡翠钢升级模板 | 注能翡翠钢 | **2** | 500k ~ 1M | 注能翡翠钢升级模板 |

玄武岩基底由物质重塑机重塑玄武岩得到（200 刻 / 80 FE·t⁻¹）。**幽匿合金块**是唯一的 2 级底座，
用玄武岩合金块时那条 2 级配方根本不会被选中 —— 换底座就是门槛。
窗口的用意是「别无脑充满」：盾牌上限 150 万要充满，打火石只有 25k~50k、充多直接过载。

字段：`base` / `inject` / `tier` / `min_energy` / `max_energy` / `result` / `duration`（默认 8）/
`seeded_energy`（默认 false）。同材料多条时取「不超过结构等级的最高等级」一条；
`min/max` 可整对省略，仅 `seeded_energy = true` 允许。

## 末地合金盾牌

把末地合金注入**盾牌**（500k~1500k FE）得 `end_alloy_shield`。

- 格挡直接沿用原版：1.21 走 `ItemAbilities.SHIELD_BLOCK`（`LivingEntity#isBlocking`），
  不认具体物品类，所以无需打标签或加事件。
- 耐久 3360（10 倍），可用末地合金在铁砧修。
- **被打碎时**（`PlayerDestroyItemEvent`）把 12 格内 `Monster` 随机甩到 16~32 格外
  （最多 16 只、每只试 8 个落点，用 `LivingEntity#randomTeleport`）。见 `EndAlloyShieldHandler`。
- 外观 = 原版盾换盾面：物品模型 `builtin/entity`（认 `isCustomRenderer`），
  `client/renderer/EndAlloyShieldRenderer` 照抄原版 `renderByItem` 但换
  `ShieldModel#renderType(我们的贴图)`（原版那段写死在 `stack.is(Items.SHIELD)`），
  贴图由 `tools/textures/gen_end_alloys.py` 只改盾正面 12×22。渲染器是懒加载单例
  （注册时 `Minecraft.getInstance()` 还没有）。`inspiration:blocking` 物品属性要在
  `client/ClientModEvents#onClientSetup` 里注册，否则举盾不换姿态。

## 种子随机能量窗口

`seeded_energy = true` 的配方窗口由**存档种子**决定（`SeededEnergyWindow`），JEI 显示 `???`：

1. 按 50% / 25% / 12.5% / 6.25% / 6.25% 取 `i ∈ [0,4]`（等价于连续抛硬币直到反面，截到 4）；
2. 在 `[0, 4-i]` 上均匀取 `j`；
3. `min = 2^i × (2/3)^(j+1) × 100K`，`max = 2^(i+1) × (2/3)^(j+1) × 100K`。

窗口恒为 `[E, 2E]`，`E` 从约 13,168 到约 1,066,666，最坏比最好贵 80 倍。
结果按「世界种子 + 配方 id」缓存（`ConcurrentHashMap`）—— **同一种子必须给出同一窗口**，
否则拆了重建就能重摇。种子取 `ServerLevel#getSeed()`（所有维度共用），客户端取不到则
`InjectionWindow.of` 返回 `null`；枪启动前先解析一次，解析不出来就不启动、不扣材料。

## 世界数据探测器

`world_data_detector` 是这套机制唯一的读数入口，**仅创造模式可得**（无配方、不进战利品表）。
右键把本存档所有种子随机配方的实际窗口打进聊天框。读数由服务端算，客户端不推算；
新增随机配方会自动出现在列表里。

# 注入合成（`injection` 包）

相关：[配方体系](../recipe/README.md) ・ [注入枪的插件槽](../machine/plugin/README.md) ・ [开发/验证总纲](../README.md)

一套由多方块结构驱动的合成方式，与机器体系独立：结构本身不耗电、不消耗灵感充能，
执行成本全部由注入枪储存的 FE 承担。

代码在 `injection/`，实现入口是 `ModInjection`（注册两个方块与绑定器）。

## 结构

| 位置 | 方块 | 外观 | 说明 |
| --- | --- | --- | --- |
| 中心 | 物质束缚器 | 矮台座（底盘 + 束腰立柱 + 顶面托盘） | 8 等离子锭 + 1 不稳核心；单槽位且限量为 1，产物回到同一槽位；被束缚的物质悬浮旋转在顶面之上 |
| 正下方 | 底座方块 | 满方块 | 用方块标签 `inspiration:injection_tier_N` 声明等级；玄武岩合金块 1 级、幽匿合金块 2 级 |
| 周围 5×5×5 | 注入枪 | 底部座 + 前伸炮管 | 发射器 + 4 翡翠钢锭；只进不出，容量 100,000 FE，最大输入 20,000 FE·t⁻¹；界面右侧四个插件槽 |

判定由 `InjectionStructure` 完成：束缚器在结构 1 格正的下方取底座，注入枪按切比雪夫距离
判定，不得超过 2（即 5×5×5 范围）。后续加更高等级的底座只需给新方块打上
`inspiration:injection_tier_N` 标签，无需改动代码——标签列表与等级换算在 `InjectionTiers`。

两个结构方块都是不完整方块：碰撞盒（`getBoundingBoxes` + `hasCustomBoxes`）与模型元素
严格对应（台座 14×10×14，炮身沿枪口方向伸出），所以看得见的地方都点得到。

## 取放物质

物质束缚器像置物台一样直接右键取放，不必每次都开界面：

| 操作 | 行为 |
| --- | --- |
| 右键（手持物品，槽内为空） | 放入一份 |
| 右键（空手，槽内有物） | 取回到手上 |
| 右键（手持物品，槽内有物） | 取回到背包 |
| **潜行**右键 | 打开界面 |

实现要点：`MatterBinderBlock` 的处理顺序是「绑定器 → 潜行开界面 → 取放」，
取放分支**必须返回 `ItemInteractionResult.CONSUME`**（返回 PASS 会继续走 `useWithoutItem`
把同一段逻辑再执行一遍）。

承放的物质由方块实体渲染器 `client/renderer/MatterBinderRenderer` 画在台座上方，
绕竖轴自转并轻微上下浮动，用来提示「束缚器里现在有没有东西、是什么」。

## 绑定与触发

手持绑定器（2 翡翠钢锭 + 末影之眼）右键物质束缚器记下坐标，再右键注入枪完成绑定；
潜行右键注入枪解除绑定。绑定关系存在物品的 CustomData（`BinderPos`）里。

绑定后注入枪的 `LINKED` 方块状态置位（正面切换为已接线贴图），并**自动把枪口转向束缚器**：
六个方向都支持，取差值最大的那个轴，所以束缚器在正上方时炮管会朝上。已绑定的枪每刻校正
一次朝向，超出范围或束缚器被拆除时绑定自动失效。

红石信号只作用在注入枪上，**上升沿**触发一次注入。只有被触发的那一支枪放电，
同一结构的其他枪存量与材料不受影响，因此玩家可以靠「给哪支枪发脉冲」来决定这次注入投入的能量。

## 判定

注入枪在启动瞬间清空自身存量并立即扣除基底与注入物质，随后按配方的能量窗口 `[min, max]` 判定：

| 放电量 | 结果 |
| --- | --- |
| 低于 `min_energy` | 不产出，材料已扣除（损失） |
| 落在窗口内 | 成功，产物写入束缚器槽位 |
| 高于 `max_energy` | 在束缚器处爆炸（半径 3） |

注入过程 8 刻，期间从枪口向束缚器播放激光粒子（`InjectionBeam`）。
**爆炸风险是设计的一部分，不要加保护。**

注意材料是在启动瞬间就扣除的，所以「低于最小 FE」= 无产物且材料损失，这一条要照写，
别改成先判定再扣。

## 配方

| 基底（束缚器） | 注入物质（枪） | 等级 | 能量窗口（FE） | 产物 |
| --- | --- | --- | --- | --- |
| 玄武岩基底 | 下界合金碎片 | 1 | 25,000 ~ 75,000 | 玄武岩合金 ×3 |
| 翡翠钢锭 | 灵感 | 1 | 50,000 ~ 150,000 | 注能翡翠钢 ×1 |
| 打火石 | 玄武岩合金 | 1 | 25,000 ~ 50,000 | 玄武岩合金打火石 ×1 |
| 盾牌 | 末地合金 | 1 | 500,000 ~ 1,500,000 | 末地合金盾牌 ×1 |
| 末地合金 | 无恒物质 | 1 | **存档种子随机** | 无恒合金 ×1 |
| 红石锭 | 灵感 | 1 | 150,000 ~ 300,000 | 注能红石锭 ×1 |
| 翡翠钢升级模板 | 注能翡翠钢 | **2** | 500,000 ~ 1,000,000 | 注能翡翠钢升级模板 ×1 |
| 铁锭 | 铯锭 | 1 | 150,000 ~ 250,000 | 盖革计数器 ×1 |
| 青金石锭 | 灵感 | 1 | 10,000 ~ 15,000 | 注能青金石锭 ×1 |
| 等离子锭 | 灵感 | 1 | 1,000,000 ~ 2,000,000 | 注能等离子锭 ×1 |

玄武岩基底由物质重塑机从玄武岩重塑得到（200 刻 / 80 FE·t⁻¹）。
**幽匿合金块**是 2 级底座（回响碎片 + 强化深板岩融合得 2 个幽匿合金，再合成块），
只有它能做上面那条 2 级配方 —— 用玄武岩合金块当底座时这条配方根本不会被选中，
换底座是最直接的门槛。
末地合金盾牌的窗口是全套配方里最贵的一档（上限 150 万 FE），因此需要先把注入枪充满再动手；
打火石那条反过来，窗口只有 25k~50k 这么窄，充多了直接过载 —— 两条配方的用意都是「别无脑充满」。

配方八个字段：`base` / `inject` / `tier` / `min_energy` / `max_energy` / `result` / `duration`
（默认 8）/ `seeded_energy`（默认 false）。同材料存在多条配方时取「不超过结构等级的最高等级」一条。
`min_energy` / `max_energy` 可以整对省略 —— 只有 `seeded_energy = true` 时允许。
序列化细节见 [配方与数据生成](../recipe/README.md)。

## 末地合金盾牌

把**末地合金**注入**盾牌**（500k ~ 1500k FE）得到 `end_alloy_shield`（末地合金盾牌）。

- 格挡行为直接继承原版 `ShieldItem`：1.21 的格挡判定走
  `ItemAbilities.SHIELD_BLOCK`（`LivingEntity#isBlocking`），不认具体物品类，
  所以自定义盾牌不需要注册任何标签或事件。
- 耐久 336 的 **10 倍**（3360），可用末地合金在铁砧上修。
- **被击碎时**（`PlayerDestroyItemEvent`，原版只在 `Player#hurtCurrentlyUsedShield`
  里把盾打碎时触发）把以玩家为中心 12 格内的敌对生物（`Monster`）随机甩到 16~32 格之外，
  每次最多 16 只、每只最多试 8 个落点；落点用 `LivingEntity#randomTeleport`，
  它会自己判区块加载 / 碰撞 / 液体，落不下来就换方向重试。
  实现见 `item/custom/EndAlloyShieldHandler`，盾牌物品本身只负责耐久。

**外观就是原版那面盾**，只是盾面换了材质，做法分三步：

1. 物品模型改成 `builtin/entity`（`assets/inspiration/models/item/end_alloy_shield.json`），
   这样 `BakedModel#isCustomRenderer()` 为 true，GUI / 手上 / 地上全都走自定义渲染器；
   模型里照抄原版盾牌的 `display` 变换，另加一条 `inspiration:blocking` 的 override 指向
   `_blocking.json`（原版那套「举到身前」的姿态）。
2. `client/renderer/EndAlloyShieldRenderer` 继承 `BlockEntityWithoutLevelRenderer`，
   照抄原版 `renderByItem` 里盾牌那一段，但用 `ShieldModel#renderType(我们的贴图)` ——
   原版那段把渲染写死在 `stack.is(Items.SHIELD)` 上，自定义盾牌走到那里会掉进 else 什么都不画。
   渲染器是懒加载单例：扩展注册时 `Minecraft.getInstance()` 还没影，而 `getCustomRenderer()`
   每帧都会被问一次。
3. 贴图是**原版盾牌展开图改的**（`tools/textures/gen_end_alloys.py`，模板
   `tools/textures/base/shield_base_nopattern.png`）：只把盾正面那 12×22 换成末地石材质，
   盾背、侧棱、把手保持原版，所以模型 UV 天然对得上，也不需要往盾牌纹饰 atlas 里塞 sprite。

`inspiration:blocking` 这个物品属性在 `client/ClientModEvents#onClientSetup` 里注册
（原版只注册在 `Items.SHIELD` 上），举盾时才会切到 blocking 的 display 变换。

无纹饰盾牌用到的贴图是 `entity/shield_base_nopattern` 那种「木纹盾面」，我们的贴图沿用它的明暗，
只换色相与颗粒，因此盾面上原本的铆钉、边框凸起都还在。

## 种子随机能量窗口

有些配方的窗口不该被玩家一次读出来，于是交给**存档种子**决定（`seeded_energy = true`）。
JEI 里这类配方的上下限一律写 `???`，只多一行「由存档种子随机决定」的说明。

抽取规则（`SeededEnergyWindow`）：

1. 按 **50% / 25% / 12.5% / 6.25% / 6.25%** 取一个 `i ∈ [0, 4]` ——
   等价于「连续抛硬币正面直到反面」，最大层截到 4；
2. 在 `[0, 4 - i]` 上**均匀**取一个 `j`；
3. `min = 2^i × (2/3)^(j+1) × 100K`，`max = 2^(i+1) × (2/3)^(j+1) × 100K`。

窗口因此永远是 `[E, 2E]` 的形状，而 `E` 从约 13,168 一路跨到约 1,066,666 ——
开档时撞上哪个量级全看运气，最坏比最好贵 80 倍。

实现口径：

- 结果按「世界种子 + 配方 id」缓存（`ConcurrentHashMap`）：同一存档里恒定，
  相邻种子、不同配方各自独立（混入配方 id 再打散种子）。**同一个种子必须给出同一个窗口**，
  否则玩家拆掉重建结构就能重摇。
- 取种子走 `ServerLevel#getSeed()`，它读的是存档的世界种子，**所有维度共用同一个值**。
  客户端拿不到种子，`InjectionWindow.of` 在这种情况下返回 `null`。
- 窗口的解析统一走 `InjectionWindow`：固定配方直接读 JSON，随机配方现算。
  注入枪启动前会先解析一次（解析不出来就不启动，材料不会被扣）。

## 世界数据探测器

`world_data_detector`（世界数据探测器）是这套机制唯一的读数入口，**仅创造模式可得**：
没有合成配方、不进任何战利品表，只能在创造物品栏里拿。

手持右键会把本存档所有种子随机配方的实际窗口打进聊天框（`WorldDataDetectorItem`）：

```
本存档的种子随机注入能量（种子 1566969352015617820）：
无恒合金：88,888 ~ 177,777 FE
```

读数一律由服务端算，客户端不做任何推算。目前只有无恒合金一条，往后新增的种子随机配方会自动出现在列表里。

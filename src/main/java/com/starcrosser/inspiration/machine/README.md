# 机器体系（`machine` 包）

相关：[插件体系](plugin/README.md) ・ [灵感充能](charge/README.md) ・ [配方体系](../recipe/README.md) ・
[方块（机器方块的模型）](../block/README.md) ・ [JEI 分类](../jei/README.md) ・ [开发/验证总纲](../README.md)

九种**用电**机器加两种**发电**机器，均由 Titanium 的组件拼装。用电机器除地核钻探者外都遵循同一套
「第 1 槽入口 + 第 2 槽出口 + 右侧部件」的布局；强能物质融合机是物质融合器的同配方上位机型，
高能物质重塑机 / 高能矿物扭曲机 / 高能灵感装配台则是下一阶段（紫色外壳）的同配方上位机型。
发电类（碱性发电机、RTG反应堆）不跑配方，只烧燃料往外送电，见《发电类》一节。

## 概览

| 机器 | 配方类型 | 能量缓冲 / 输入功率 | 灵感充能 |
| --- | --- | --- | --- |
| 物质融合器 | 物质融合 | 60,000 FE / 1,000 FE·t⁻¹ | 1 mB/刻 |
| 强能物质融合机 | 物质融合 | 120,000 FE / 2,000 FE·t⁻¹ | 2 mB/刻 |
| 物质重塑机 | 物质重塑、右键转化 | 200,000 FE / 4,000 FE·t⁻¹ | 2 mB/刻 |
| 矿物扭曲机 | 矿物扭曲 | 400,000 FE / 8,000 FE·t⁻¹ | 2 mB/刻 |
| 灵感装配台 | 灵感装配 | 300,000 FE / 6,000 FE·t⁻¹ | 2 mB/刻 |
| 地核钻探者 | 无（向下掏竖井） | 4,000,000 FE / 20,000 FE·t⁻¹ | 16,000 mB/次 |
| 高能物质重塑机 | 物质重塑、右键转化 | 400,000 FE / 8,000 FE·t⁻¹ | 4 mB/刻 |
| 高能矿物扭曲机 | 矿物扭曲（时运 12） | 800,000 FE / 16,000 FE·t⁻¹ | 4 mB/刻 |
| 高能灵感装配台 | 灵感装配 | 600,000 FE / 12,000 FE·t⁻¹ | 4 mB/刻 |
| 碱性发电机 | 无（烧碱性物质） | 1,000,000 FE / 输出 8,000 FE·t⁻¹ | 无 |

九台加工机器都是只进不出的用电设备：能量只能被自身消耗，不能被线缆抽走。
两台发电机正相反：缓冲只出不进（`maxReceive = 0`），每刻主动推给相邻方块，也能被线缆抽取。
所有机器界面右侧都带四个插件槽（见 [插件体系](plugin/README.md)）。

### 高能机型

「高能」是第三阶段的上位机型，主色调取无恒合金的淡紫，统一规则是：

- 电容、灵感充能容量、处理速度都是**上一阶段的 2 倍**；
- 每刻耗电与每刻灵感充能消耗也是 **2 倍** —— 于是一次作业的总耗电不变，只是快一倍；
- 配方与对应的普通机型**共用一套**（同一种配方类型、同一个 JEI 分类），
  因此「只有高能机型能做」的配方靠输入槽数量或流体槽数量天然区分；
- 倍率全部写在各自的方块实体里（`baseSpeed()` / `baseChargeCapacity()` / 私有的
  `energyCost(...)`），基类 `InspiredMachineTile` 的插件结算流程不用改。

| 高能机器 | 相对普通机型的额外改动 |
| --- | --- |
| 高能物质重塑机 | **无**（纯粹容量翻倍 + 快一倍） |
| 高能矿物扭曲机 | 等效时运固定抬到 **12**（取「配方声明值」与 12 的较大者）；产出上限按 13 倍预留输出槽 |
| 高能灵感装配台 | 物品输入槽 4 → **6**（界面 2 列 × 3 行）、流体输入槽 1 → **2** |

三台机器都由「普通机型 + 高能核心 + 4 无恒合金 + 3 对应的注能锭」合成，形状与其他机器一致
（见下《机器本体的合成形状》）。注能锭由注入合成得到：青金石锭 ← 灵感（10k~15k FE）、
红石锭 ← 灵感（150k~300k FE）、等离子锭 ← 灵感（1M~2M FE）。

### 发电类

两台发电机都继承 `PowerGeneratorTile`（`machine/blockentity`），与 `InspiredMachineTile`
是并列的两条链：**不消耗灵感充能**，能量缓冲 `maxReceive = 0`、`maxExtract` 留给线缆与相邻方块。
界面沿用同一套网格（能量条 (8,14)、燃料槽 (44,30)、进度条 (78,38)、输出槽 (116,39)），
进度条是「正着走」的：从 0 走到本份燃料的燃烧刻数。

| 机器 | 燃料 | 燃烧刻数 | 每刻产电 | 副产物 |
| --- | --- | --- | --- | --- |
| 碱性发电机 | 碱性值 > 0 的物品 | 12,000 | 100 × 碱性值 FE | 无 |
| RTG反应堆 | 辐射值 > 0 的物品 | 24,000 | 1000 × 辐射值 FE | x 个核废料（x = 辐射值） |

- **燃料在开工瞬间就被扣掉**，所以 `canBurn` 必须先认 `burningValue` 再回查槽位 ——
  否则燃料槽一空，进度条立刻冻在第一格（这是第一版踩过的坑）。
- **缓冲满了会停下来等**：`canBurn` 要求「剩余空间 ≥ 这一份燃料每刻的产能」，
  燃料不会白白烧掉。因此想测一整个燃烧周期，得在每刻把电抽走。
- **烧完靠自己的计数器**（`burnedTicks`）判定，不信进度条归零：
  缓冲满时 Titanium 的 `MultiProgressBarHandler` 会把进度条直接打回 0 且**不回调**
  `onFinishWork`，副产物就丢了。`finishBurn()` 因此写成可重入（强度归零即返回）。
- **速度插件 = 功率翻倍**：进度条每刻推进量与每刻产能同步 ×speed，燃烧时间同比缩短，
  一份燃料的总发电量与每分钟副作用的**次数**都不变（副作用按「燃烧单位」累计，不按真实刻数）。
- **RTG 的辐射副作用**：每烧满 1200 个燃烧单位，向所在区块释放 `(x-1)^3` 点辐射；
  x > 9 时再以 `(x-9)/1000` 的概率当场爆炸（威力 6，会毁方块，刻意不加保护）。
  立方用 long 先算再截断，避免数据包把辐射值改大时溢出成负数。

自检结论（临时类跑完已删）：碱性发电机烧 1 铯粉（碱性 4）产 4,800,000 FE；
RTG 烧 1 钫锭（辐射 3）产 72,000,000 FE、吐 3 个核废料、区块辐射 +160（20 次 × 8）；
两台都只收对应的燃料（钻石被拒），烧完自动停机。

### 机器 tooltip

`machine/client/MachineTooltips` 按物品 ID 给所有机器挂说明：加工类写配方类型，
发电类写发电机制。键是 `tooltip.inspiration.machine.<机器名>`，新增机器只要往
`MACHINES` 里加一行、再补两种语言的文案（走 tooltip 事件是因为机器方块由 Titanium
一次注册成型，拿不到自定义物品类去覆写 `appendHoverText`）。

**一个键可以写多行**：语言值里用 `\n` 分隔，`MachineTooltips` 取到字符串后按换行切开、
逐行挂上去（Minecraft 不会自己把语言值里的换行折成多行，必须手动切）。

文案风格（照现有 11 条写，新增机器沿用）：

- 加工类首行固定是「配方类型：xxx」，上位机再补一行差异（速度 ×2、额外槽位等）；
- 发电类是「投入……发电。」→「发电量：…；燃烧时间：…。」→「x 为物品……值」，
  副作用与副产物各占一行。

`alkaline_reactor` 的显示名是**碱性发电机**、`rtg_generator` 是 **RTG反应堆**
（内部 ID 与语言键仍是 `alkaline_reactor` / `rtg_generator`，别去改 ID）。

### 机器本体的合成形状

所有机器（含上位机型）都由 `ModRecipesProvider#machine(...)` 生成，形状统一为：

```
M S M
S C S
M X M
```

- **M 主要材料**：四角 + 底中，共 5 份；
- **S 次要材料**：上中 + 中行两侧，共 3 份；
- **C 核心**：正中 1 份，按阶位取强化核心 / 强能核心 / 高能核心；
- **X 下级机器**：升级机型填被升级的那台机器 —— 此时底中被占，主要材料只剩四角 4 份；
  基础机型没有下级机器，X 位置仍填主要材料。

「主要材料」是按**用量**定的（占 5 份的那个），不按材料贵贱；所以地核钻探者的主要材料是
翡翠钢锭、次要材料才是更金贵的思维矩阵锭。

| 机器 | M 主要材料 | S 次要材料 | C 核心 | X 下级机器 |
| --- | --- | --- | --- | --- |
| 物质融合器 | 铁锭 | 红石锭 | 强化核心 | — |
| 强能物质融合机 | 注能翡翠钢 | 红石锭块 | 强能核心 | 物质融合器 |
| 地核钻探者 | 翡翠钢锭 | 思维矩阵锭 | 强能核心 | — |
| 物质重塑机 | 翡翠钢锭 | 红石锭块 | 强能核心 | — |
| 矿物扭曲机 | 翡翠钢锭 | 青金石锭块 | 强能核心 | — |
| 灵感装配台 | 翡翠钢锭 | 等离子锭 | 强能核心 | — |
| 高能物质重塑机 | 无恒合金 | 注能红石锭 | 高能核心 | 物质重塑机 |
| 高能矿物扭曲机 | 无恒合金 | 注能青金石锭 | 高能核心 | 矿物扭曲机 |
| 高能灵感装配台 | 无恒合金 | 注能等离子锭 | 高能核心 | 灵感装配台 |
| 碱性发电机 | 翡翠钢锭 | 红石锭 | 发电核心 | — |
| RTG反应堆 | 无恒合金 | 注能红石锭 | 反应核心 | — |

**核心本体**（强化核心 / 强能核心）与**注入结构件**（物质束缚器、注入枪）不走这个形状 ——
它们要么本身就是产物、要么材料不足三种，保持各自原来的样子。

## Titanium 约定

继承链 `BasicTile → ActiveTile → PoweredTile → MachineTile`，本项目不走这条链的中间层，
机器统一继承 `InspiredMachineTile`（见下）。框架要点：

- 继承关系：`InspiredMachineTile` 先
  `addInventory` / `addProgressBar` —— 部件靠组合添加，GUI 由 `BasicAddonScreen` 自动绘制。
- `MachineTile#onActivated` 里才会 `openGui()`；继承 `ActiveTile` / `PoweredTile` 的
  方块实体必须自己覆写 `onActivated` 调 `openGui(player)` 并返回 SUCCESS，否则右键不开界面。
- 注册一次成型：`DeferredRegistryHelper#registerBlockWithTile` 同时注册方块、方块物品、
  方块实体与能力。**机器方块不会进 `ModBlocks.BLOCKS`**，因此必须单独补战利品表与方块标签。
- 自动化写入走 `level.getCapability(Capabilities.ItemHandler.BLOCK, pos, ...)`，
  不用 `tile.getItemHandler(null)`（方块刚放下时可能返回 null）；Titanium 的能力**按朝向**注册。
- 改槽位内容用 `tile.getHandlerFromName("名字")`（返回 `ItemStackHandler`）；
  能量用 `PoweredTile#getEnergyStorage().setEnergyStored(v)`（绕过输入功率限制）。

### 界面网格

机器界面固定 **176×184**，新增部件时按此避让：

| 部件 | 位置 |
| --- | --- |
| 能量条 | (8, 14)，12×50 |
| 输入槽 | (44, 30)；多槽机型往下排，强能融合机的 3 槽占 30/48/66 |
| 输出槽 | (116, 39) |
| 充能槽 / 充能罐 | (150, 74) / (150, 14)，18×56 |
| 侧向配置按钮 | 同一行 y=84，x 从 8 起，每个间隔 18 |
| 插件槽 | 背景底板 (175, 4)，槽位从 (180, 11) 起 |

灵感装配台与高能灵感装配台换了另一套排布（要在有限宽度里塞下 4~6 个输入槽与 1~2 个流体罐）：

| 部件 | 灵感装配台 | 高能灵感装配台 |
| --- | --- | --- |
| 流体罐 | (26, 14) | (26, 14)、(44, 14) |
| 输入区 | (52, 25)，2×2 | (66, 16)，2 列 × 3 行 |
| 进度条 / 输出槽 | (104, 34) / (128, 34) | 同左 |

`SidedInventoryComponent(name, x, y, 槽数, 侧栏序号)` 的 `setRange(w, h)` 只是界面上的列×行；
`SidedFluidTankComponent(name, 容量, x, y, 序号)` 的**容量是第 2 个参数**，顺序不同别照抄。

#### 侧向配置按钮的文字标签

Titanium 的朝向按钮本体是个 14×14 的小方块，只靠颜色区分归属，单看界面分不出哪个是输入。
`machine/client/FacingLabelAddon` 在按钮**正上方**补一行短标签，颜色取组件自己的 `getColor()`
压暗 62%，跟槽位高亮是同一套配色。

位置是唯一的难点，改动前先看清楚三件事：

- 按钮画在最底一行 **y=84**，而 Titanium 的玩家背包从 **y=102** 开始 —— 按钮下方只剩 4 像素，
  放不下字，所以标签只能往上：`y = 按钮y − 1 − 9`（字高 9 + 间隙 1），落在 74~83 这段空白里。
- 一行里相邻按钮 **间隔 18 像素**，所以标签控制在**两个汉字（16 像素）**以内，英文别超过 3 个字母。
- x 要对准按钮中心（按钮中心 = `facingHandlerX + 7`），直接交给 `drawCenteredString`。

翻成数：标签的语言键是 `gui.inspiration.facing.<组件名>`，靠 `addFacingLabels(...)`
从 `IFacingComponent#getName()` 拼出来，新增机器只要在覆写的 `initClient()` 里把组件传进去。
`InspiredMachineTile` 已经给自己的充能槽与充能罐挂好了标签，子类 `super.initClient()` 就带上。

`initClient()` **必须标 `@OnlyIn(Dist.CLIENT)`**：addon 是客户端类，不加的话服务端做类校验时会
去加载它，直接被 dist cleaner 判错（和 `InjectionGunTile` 补插件背景底板同一个坑）。

### InspiredMachineTile

带灵感充能消耗的机器继承它（`machine/blockentity/InspiredMachineTile`），提供：

- 灵感充能槽 + 充能罐体（容量 16,000 mB，1 灵感 = 1000 mB）；
- 罐体只允许 `Action.FILL`（只进不出），所以机器自身扣减必须走 `drainForced`，
  普通 `drain` 会被拦；罐体标 `@Save` 即可存档，不需要额外代码；
- 每刻刷新插件倍率并把结果写回各部件。

子类只需实现三个钩子：`chargePerTick()` / `baseEnergyCapacity()` / `getProgressBar()`。
另有三个可覆写的倍率钩子，默认都是「1 倍」（`baseSpeed()` 是 1、`baseChargeCapacity()` 是 16,000 mB），
强能物质融合机就是把它们改成 2 倍来实现「同配方更快更贵」的：
`baseSpeed()` 决定进度条每刻推进量，`baseChargeCapacity()` 决定充能罐基准容量，
配方侧每刻耗电的倍率写在各机器自己的 `energyCost(...)` 里。
（给基类加抽象方法前先确认子类没有同名方法——`getProgressBar` 曾撞过名。）

## 物质融合

输入顺序无关；`FusionRecipe` 有一个可选的 `third_input`，材料数量必须与**非空输入槽数量**一致，
所以 3 材料配方天然只有三槽的强能机型能做，两台机器的配方显示共用同一个 JEI 分类。

每种材料还可以用 `first_count` / `second_count` / `third_count`（默认 1）声明**一次消耗几个**：
槽里要一次攒够数量才匹配，作业结束时按各自数量扣除。数量只是同一槽的堆叠，不占额外槽位，
因此三槽机型照样做得动 4 + 1 + 4 这种偏重的配方；JEI 对需要多个的槽位会直接画出数字。

| 输入 A | 输入 B | 输入 C | 产物 | 耗时 / 每刻耗电 |
| --- | --- | --- | --- | --- |
| 绿宝石 | 铁锭 | — | 翡翠钢锭 ×2 | 200 刻 / 40 FE·t⁻¹ |
| 玄武岩 | 远古残骸 | — | 玄武岩合金 ×2 | 400 刻 / 120 FE·t⁻¹ |
| 思维晶体 | 紫水晶碎片 | 下界石英 | 思维矩阵锭 | 600 刻 / 300 FE·t⁻¹ |
| 黑曜石 ×4 | 末影珍珠 | 紫珀块 ×4 | 末地合金 | 800 刻 / 600 FE·t⁻¹ |

强能物质融合机跑这些配方时：速度 ×2、每刻耗电与每刻耗充能 ×2
（上表的耗时与耗电是**基准值**，与基础机型一致；JEI 里显示的就是基准值）。

## 物质重塑

可执行全部右键转化配方，另外支持机器专属的重塑配方：可选的第二输入、以及一次消耗
多个主材料（字段 `input_count`）。已实现：

| 输入 | 产物 | 耗时 / 每刻耗电 |
| --- | --- | --- |
| 煤炭 ×1 | 褐煤 ×2 | 200 刻 / 80 FE·t⁻¹ |
| 红石 ×3 | 红石锭 | 200 刻 / 80 FE·t⁻¹ |
| 青金石 ×3 | 青金石锭 | 200 刻 / 80 FE·t⁻¹ |
| 盔甲纹饰模板 | 翡翠钢升级模板 | 400 刻 / 200 FE·t⁻¹ |
| 玄武岩 | 玄武岩基底 | 200 刻 / 80 FE·t⁻¹ |
| 玄武岩合金 | 玄武岩合金钻头 | 600 刻 / 400 FE·t⁻¹ |
| 钻石 | 等离子锭 | 600 刻 / 400 FE·t⁻¹ |
| 强能核心 | 发电核心（炉心转绿） | 600 刻 / 400 FE·t⁻¹ |
| 高能核心 | 反应核心（炉心转红） | 800 刻 / 600 FE·t⁻¹ |
| 装备回炉（数据表驱动，共 41 条） | 对应材料 | 160 刻 / 60 FE·t⁻¹ |

同时支持多种配方族，因此抽了「任务」层：`ReshaperTask` 统一描述一次重塑该做什么，
由 `ReshaperTaskResolver` 从右键转化配方与重塑配方里查出来。

高能物质重塑机的界面与基础机型完全一致（输入 (44,30) 1 列 × 2 行、输出 (116,39)、
进度条 (78,38)），跑同一套配方，**没有任何额外效果**，只是按高能规则容量翻倍、速度快一倍。

## 矿物扭曲

单输入槽，放入矿石产出对应粗矿，产量按配方声明的等效时运（默认 6）掷出。倍率公式与原版
`ApplyBonusCount.OreDrops` 一致（时运 6 时 1~7 倍，期望 3.625 倍），已与反编译源码逐行核对。

- 普通矿 400 刻 / 300 FE·t⁻¹；稀有矿（金、钻石、绿宝石、下界金）600 刻 / 400 FE·t⁻¹。
- 远古残骸不受时运影响、无恒矿石直接产出无恒物质，两者都没纳入配方。
- 高能机型把等效时运抬到 **12**（1~13 倍，期望 7.75 倍），其余数值按高能规则翻倍。
  JEI 里显示的产量区间用的是配方基准值（6），因为它只有一套配方。

## 灵感装配

普通机型是四个物品输入槽 + 一个流体输入槽；高能机型是**六个物品输入槽（2 列 × 3 行）+
两个流体输入槽**，两者共用一个输出槽。

- 材料与槽位不要求一一对应：只要每种材料都能在输入区里各找到一份即可。
  顺序无关的指派由 `AssemblingRecipe#resolveSlots` 用回溯法完成，因此 5~6 种材料的配方
  天然只有六槽的高能机型能做。
- 配方可声明**最多两条**流体原料（种类 + 用量，记录类 `FluidRequirement`），
  由 `resolveFluids` 用同样的回溯法指派到罐位；两条流体的配方同样只有高能机型能做。
  流体输入槽不收灵感充能，灵感充能仍走基类的充能罐。

已实现（均为 300 刻 / 200 FE·t⁻¹）：

| 材料 | 产物 |
| --- | --- |
| 等离子锭 + 红石锭 | 电容插件 |
| 等离子锭 + 灵感 | 灵感插件 |
| 等离子锭 + 糖 | 速度插件 |
| 等离子锭 + 铁锭 | 电容降级插件 |
| 强能核心 + 钫盐 + 强化深板岩 | 高能核心 |

高能核心是「强能核心之上」的能量部件，需要三样材料同时在输入区里，缺一不可；
强化深板岩（`minecraft:reinforced_deepslate`）只有地核钻探者能挖到，所以它是中期门槛件。

灵感装配台自身由 3 等离子锭 + 5 翡翠钢锭 + 1 强能核心合成；
高能灵感装配台由灵感装配台 + 高能核心 + 4 无恒合金 + 3 注能等离子锭合成。

## 地核钻探

唯一一台不跑配方的机器：它把正下方掏成一条竖井，直到撞上挖不动的方块（基岩等）。
自身由 3 思维矩阵锭（十字三个位）+ 5 翡翠钢锭 + 1 强能核心合成（`JMJ / MCM / JJJ`）。

- **一次作业一次性结清**：抽干全部电量 + 16,000 mB 灵感充能 + 1 点钻头耐久。
  电量必须**充满容量**才允许开工 —— 而容量是会被插件改写的，所以装上电容降级插件
  （×0.67，4 M → 2.68 M）之后要攒的电一下就少了三分之一。这条不写进 tooltip。
- **钻头**：唯一的输入槽只收 `DrillBitItem`（玄武岩合金钻头，耐久 128，玄武岩合金锭经
  物质重塑 600 刻 / 400 FE·t⁻¹ 得到）。耐久耗尽时原版 `hurtAndBreak` 会把这一格直接抽走，
  也就是钻头报废；下一轮没钻头就开不了工。
- **进度**：开工时扫一遍竖井，进度条上限 = 竖井格数 × `TICKS_PER_BLOCK`(2)。
  空气与流体也算格数（照样要花时间穿过），流速插件会按比例缩短总时长。
  扫描结果缓存 20 刻，且**止于未加载区块**，不会为了数格子去生成地形。
- **掉落**：统一按精准采集结算（`Block.getDrops` 传一把带精准采集的虚拟镐），
  两个刻意的例外写在 `CoreDrillerTile#dropsFor` —— 刷怪笼不掉落自身，
  强化深板岩掉落自身（它在原版里的掉落表是空的，这也是拿到它的唯一途径）。
- **收集**：产物优先用 `Capabilities.ItemHandler.BLOCK` 塞进机器**正上方**的容器，
  容器不存在或塞不下时，剩余部分在机器上方就地掉出。

自检结论（临时类跑完已删）：满电机器的竖井 y91~95 全变空气、y90 基岩保留，
上方箱子收到 石头/泥土/强化深板岩 各 1 且**没有刷怪笼**；差 1 FE 不满的机器进度恒为 0；
装电容降级插件、容量 2,680,000 且刚好攒满时机器正常开工；三种消耗（4 M 电、16,000 mB 充能、
1 点耐久）逐项核对无误。

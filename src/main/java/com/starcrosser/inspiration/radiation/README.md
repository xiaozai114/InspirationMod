# 辐射机制

> 相关：[方块登记点](../block/README.md) ・ [配方与数据生成](../recipe/README.md) ・ [通用坑](../README.md)

一套独立的区块级污染系统。辐射不绑定维度、不绑定方块类型，任何物品/方块登记一个数值就会参与结算。

## 三个量

| 量 | 含义 | 存放 |
| --- | --- | --- |
| **辐射值** | 单个物品/方块的属性，单位是「每秒注入多少点辐射」 | NeoForge 数据地图（可被数据包覆盖） |
| **区块辐射** | 某个区块当前累积的辐射 | 每维度一份 `SavedData`，随存档落盘 |
| **玩家辐射** | 玩家体内累积的辐射 | 玩家 attachment，随玩家存档落盘 |

## 结算规则

### 每秒

- **方块**：辐射值为 x 的方块，只要六面中**任意一面接触空气**，就向所在区块注入 x 点。
  被完全包住（比如埋在地里的矿）不注入 —— 这正是「钫盐矿不露天生成」的设计前提。
- **物品**：辐射值为 x 的物品放在玩家背包里（含装备栏与副手），向**玩家所在区块**注入
  **x × 件数**。九件压成一格方块时块值是单件的 9 倍，物品按件数计才和这条对上；
  方块物品（钫盐矿、钫盐块、钫块）同样走这条 —— 它们在地上和在身上都算辐射源。
- **玩家**：站在辐射区块里，每秒吸收一次「该区块当前的值」。

### 每小时（72000 刻 = 3600 秒）

区块，设当前值为 x：

- 向四个正方向中**辐射值严格更低**的邻区块各传播 `⌊x/100⌋` 点；
- 额外自发衰减 `⌊x/10⌋` 点；
- 传播出去的份额**从源区块扣除**（是「传播」而不是「复制」）。

玩家，设当前值为 x：

- 自发衰减 `⌊x/10⌋`，并把另外 `⌊x/10⌋` 倒回所在区块；
- 也就是说玩家体内每小时掉 `2⌊x/10⌋`，其中一半进入脚下区块。

三条口径（如与预想不符，改这里即可）：**只向四个正方向传播**（不含斜角）、
**传播从源扣除**、**物品按件数累计**。

### 玩家中毒

每一层完全包含上一层，因此按阈值从低到高覆盖即可（效果持续 3 秒、每秒刷新，
离开辐射区自然消退）：

| 阈值 | 表现 |
| --- | --- |
| > 10K | 虚弱 I、饥饿 I |
| > 50K | 虚弱 II、挖掘疲劳 I |
| > 100K | 挖掘疲劳 II，且**治疗被换算**：本该回复的生命值按 1:10 变成辐射衰减 |
| > 500K | 缓慢 I、失明 |
| > 1M | 凋零 I、饥饿 II、缓慢 II、挖掘疲劳 III、虚弱 III |

死亡后玩家辐射减半（从末地返回等非死亡克隆则原样搬运）。

## 辐射源（钫盐系列）

处理流程与铯盐完全对应，只是全流程产物都带辐射：

| 物品/方块 | 辐射值 |
| --- | --- |
| 钫盐矿、粗钫盐、钫盐 | 1 |
| 钫粉、钫锭 | 3 |
| 钫盐块（9 钫盐） | 9 |
| 钫块（9 钫锭） | 27 |

钫盐矿、钫盐块、钫块这三个**方块物品**在物品表里也各登记了一份同样的数值，
所以它们放在地上（方块表）和拿在身上（物品表）都参与结算 —— 数值表在
`data/inspiration/data_maps/{item,block}/radiation.json`，两张同名、各管一个注册表。

- 钫盐矿在世界生成阶段放在**地狱 Y 95~124**（上层），稀有度低于铯盐矿，
  且 `discard_chance_on_air_exposure = 1.0` —— 露天的一律不生成。
  矿脉底色是地狱岩（贴图脚本用 `tools/textures/base/netherrack.png` 作底、只叠矿脉像素）。
- 钫是碱类物品且碱性略强于铯，因此 `AlkaliItem` 的爆炸半径取 **6f**（铯是 4f）。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `RadiationDataMaps` | 两张数据地图（物品表 `data_maps/item/radiation.json`、方块表 `data_maps/block/radiation.json`） |
| `Radiation` | 数值查询与短串格式化（`10.0K` / `1.20M`） |
| `RadiationSavedData` | 区块辐射表：读改写、每小时传播与衰减、NBT 序列化 |
| `RadiationBlockTracker` | 每维度的「辐射方块位置」索引：区块加载时排队扫描，放置/破坏增量维护 |
| `RadiationAttachments` | 玩家辐射的 attachment 类型与读写 |
| `RadiationEffects` | 中毒分层、阈值常量、治疗换算判定 |
| `RadiationTicker` | 每刻驱动：扫描队列、每秒结算、每小时结算 |
| `RadiationEvents` | 事件入口：放置/破坏/区块加载卸载、死亡减半、治疗换算、停服清索引 |
| `item/GeigerCounterItem` | 盖革计数器：右键读出区块值与玩家值 |
| `client/RadiationTooltips` | 给带辐射的物品挂一行 tooltip（客户端限定） |

## 实现要点

- **数值走数据地图**：`DataMapType.builder(Id, 注册表, codec)`，两张表同名但分属不同注册表，
  因此文件分别在 `data_maps/item/` 与 `data_maps/block/` 下。加了 `.synced(...)`，
  客户端才能读到数值来画 tooltip。
- **不能每刻全图扫描**：`RadiationBlockTracker` 只在区块加载时排队扫描，
  每刻最多处理 2 个（`SCANS_PER_TICK`）；扫描前先查区块段的**调色板**，
  段里没出现过登记过的方块就直接跳过，因此绝大多数段只花「把存储里的整数读一遍」的时间。
- **传播要双缓冲**：`tickHourly()` 先在快照上算完所有增减再统一写回，
  否则结算次序会影响结果（先传播的区块会把值传给还没结算的邻居）。
- **效果必须「先移除再施加」**：原版 `addEffect` 在已有同级或更强的同种效果时会直接忽略，
  降级（虚弱 II → 虚弱 I）就永远退不回去。
- **玩家的 attachment 默认不随死亡拷贝**，`RadiationEvents#onClone` 里显式搬运，
  顺便做死亡减半。
- 常量：每秒 = 20 刻、每小时 = 72000 刻、每刻扫描 2 个区块，
  分别写在 `RadiationTicker` 与 `RadiationBlockTracker` 里。

## 怎么验证

自检类的套路见[源码树 README](../README.md)：`ServerStartedEvent` 里放方块、塞物品，
`ServerTickEvent.Post` 若干刻后读值。这套机制额外提供两个便于自检的入口：

- `RadiationSavedData#get(level)` 直接读区块值；`#tickHourly()` 可以手动推进一小时，
  不必真等 3600 秒；
- `RadiationBlockTracker#trackedCount()` / `pendingCount()` / `snapshot()` 用于核对索引内容。

盖革计数器本身就是给玩家用的验证工具：手持右键会在 action bar 打出
「区块 x ・ 体内 y（中毒程度）」。
